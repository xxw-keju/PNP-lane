# 部署与数据迁移

发行包与运行数据分离。直接安装新包、运行 `init` 即可从公开任务源建立新缓存，不需要复制原账号的状态。

已有数据不在发行包中，以下迁移均是另行进行的本地操作：

- `catalog/` 可重新联网生成；更换仓库时应重新生成。新版本刷新时会扫描所有登记账号的 fork；添加账号后等一次完整刷新再采用分支快照。
- `assessments/events/` 是带题面指纹的评估记录，可在同一项目内复制；`--agent` 的 id 应保留在新配置中。过期题面会自动失效。
- `jobs/` 及 `job-index/` 包含仓库、日志和作业的绝对路径。它们不是可直接跨机器恢复的纯数据包；应保留旧部署用于完成在途任务，或只作为历史归档。
- 已经推送或创建 PR 的 job 不要重新 prepare 成新任务，否则可能重复操作。原 job 里冻结了账号、提交和源码指纹。
- 会话观察配置需要在新机器重新填写本地 transcript 或 Codex 数据库路径；不复制认证文件。
- GitHub 登录在新机器执行 `gh auth login`；Lean/Mathlib 按官方仓库说明安装，不从本包导入。

当前发行版本的 runtime 数据默认位于 `~/.local/state/pnp-lane/`，与旧版本的代码目录分开。网页反馈和进程信息写在该目录下的 `dashboard/`。网页写 API 仅用于选择发布账号，无批量数据导出或迁移命令。

## 0.4.0 多账号

升级后先执行 `account add LOGIN` 验证原账号并建立 registry。已有作业的 `account` 和 `author_email` 保留，不随默认账号改变。旧作业没有凭据配置记录时，按它保存的账号查询 registry，因此要保留原账号的登录及登记信息，直到恢复/验证结束。

`accounts.json` 包含用户名、邮箱、gh 配置目录和选择历史，属于本地私有配置，不能打进公共发行包。它不含 token。跨机器应重新登录并登记，不能直接搬迁里面的 gh 路径。在途作业的凭据配置已单独保存，修改登记目录不会追溯替换它们。

升级程序会使旧预编译环境指纹失效，应重新 precompile；日常切换账号本身不使编译记录失效。已有任务不会因默认账号切换自动复制或重新发布。
