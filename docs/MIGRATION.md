# 部署与数据迁移

发行包与运行数据分离。直接安装新包、运行 `init` 即可从公开任务源建立新缓存，不需要复制原账号的状态。

已有数据不在发行包中，以下迁移均是另行进行的本地操作：

- `catalog/` 可重新联网生成；更换 GitHub 账号或仓库时应重新生成，不能沿用旧 fork 分支快照。
- `assessments/events/` 是带题面指纹的评估记录，可在同一项目内复制；`--agent` 的 id 应保留在新配置中。过期题面会自动失效。
- `jobs/` 及 `job-index/` 包含仓库、日志和作业的绝对路径。它们不是可直接跨机器恢复的纯数据包；应保留旧部署用于完成在途任务，或只作为历史归档。
- 已经推送或创建 PR 的 job 不要重新 prepare 成新任务，否则可能重复操作。原 job 里冻结了账号、提交和源码指纹。
- 会话观察配置需要在新机器重新填写本地 transcript 或 Codex 数据库路径；不复制认证文件。
- GitHub 登录在新机器执行 `gh auth login`；Lean/Mathlib 按官方仓库说明安装，不从本包导入。

当前发行版本的 runtime 数据默认位于 `~/.local/state/pnp-lane/`，与旧版本的代码目录分开。网页反馈和进程信息写在该目录下的 `dashboard/`。本包的网页 API 为只读，无批量数据导出或迁移命令。
